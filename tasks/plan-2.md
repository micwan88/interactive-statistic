# Plan 2 — Refactor the whole site from JS to TypeScript

## Context / Findings
- Stack: Vite + React 18 + Tailwind v3, SPA with HashRouter. All source currently `.jsx`/`.js`.
- Files to convert under `src/`: `main.jsx`, `App.jsx`, `demos.js`, `style/theme.js`,
  `components/PageLayout.jsx`, `pages/{Home,BinomialNormal,CLT,RSquared}.jsx`.
- `tailwind.config.js` imports `./src/style/theme.js` → must follow the rename → convert to `tailwind.config.ts`.
- `index.html` references `/src/main.jsx` → update to `.tsx`.
- **Blocker:** Node/npm not installed locally → cannot run `tsc`/`vite`/`npm install` to verify. Authored by static reasoning.
- **No deploy risk:** `deploy.yml` triggers only on push to `main`; this work lands on branch `requirement-2`.

## Key decisions
- **Type-check in build:** `package.json` build script → `tsc && vite build` (Vite alone only strips types; `tsc` does the real check). Single `tsconfig.json` with `strict: true`, `include: ["src"]`.
- **Dev deps added:** `typescript`, `@types/react`, `@types/react-dom`. `package-lock.json` regenerated by `npm install` in CI (can't generate locally).
- **Imports:** drop `.jsx`/`.js` extensions (keep `.css`) under `moduleResolution: "bundler"`.
- **Typing approach:** explicit prop interfaces for every component; helper functions returning inline-style objects annotated `: CSSProperties` (prevents literal-widening errors); state generics where the initial value underspecifies (`useState<Record<…>>`, `useState<number | null>`, etc.). Inline JSX event handlers left unannotated (React infers them).
- **`postcss.config.js` stays `.js`** — PostCSS config isn't loaded as TS without extra tooling; not part of the app code.
- Behaviour unchanged — pure language/type migration, no logic edits.

## Review

### What changed
- All 9 `src` modules converted to `.ts`/`.tsx`; `tailwind.config.js`→`.ts`; `index.html` entry → `/src/main.tsx`.
- Added `tsconfig.json` (`strict`, `noUnusedLocals/Parameters`, bundler resolution, `include: ["src"]`) and dev deps `typescript`, `@types/react`, `@types/react-dom`. Build script now `tsc && vite build` so CI type-checks.
- Types added: prop interfaces for every component (`PageLayoutProps`, `BinomialChartProps`, `BarProps`, `HistogramProps`, inline prop types), exported `Demo` interface, numeric helper signatures, `useState`/`useRef` generics where the initial value underspecifies, and `: CSSProperties` on the two `btnStyle` helpers (prevents string-literal widening on `cursor`/etc.). The two unguarded `clearInterval(intervalRef.current)` call sites (logically non-null while rolling) use `!`.
- Behaviour untouched — pure language migration. Removed only the orphaned `as [string,string][]` cast I briefly added (inferred `string[][]` suffices).
- `postcss.config.js` deliberately left as `.js` (PostCSS doesn't load `.ts` configs without extra tooling). `assets/jsx/*.jsx` are the documented original migration sources, not built site code — left as-is.
